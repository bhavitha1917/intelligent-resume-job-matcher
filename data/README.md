# Dataset Setup

This project uses three datasets. **Raw datasets are not committed to Git** (see
`.gitignore`) — you must download them yourself and place them at the exact
paths below. The application and notebooks will raise a clear error naming the
missing path if a dataset is absent, and the core pipeline can still be
exercised end-to-end using the tiny bundled demo set in `data/external/demo/`.

---

## 1. Kaggle Resume Dataset

Source: https://www.kaggle.com/datasets/snehaanbhawal/resume-dataset

Expected local path:

```
data/raw/Resume/Resume.csv
```

Expected columns: `ID, Resume_str, Resume_html, Category`

Also expected (the PDF/category folders shipped with the same Kaggle dataset):

```
data/raw/data/data/<CATEGORY>/<ID>.pdf
```

**Status in this repo:** already present locally (not tracked by Git).

Download steps:
1. Download the dataset zip from Kaggle (requires a free Kaggle account).
2. Extract it so `Resume.csv` ends up at `data/raw/Resume/Resume.csv` and the
   per-category PDF folders end up at `data/raw/data/data/<CATEGORY>/`.

---

## 2. Kaggle LinkedIn Job Postings (2023-2024)

Source: https://www.kaggle.com/datasets/arshkon/linkedin-job-postings-2023-2024

Expected local path:

```
data/raw/linkedin_job_postings/postings.csv
```

Relevant fields used by this project: `job_id, title, description,
formatted_experience_level, location, work_type, skills_desc, company_id`.

**Status in this repo: NOT yet downloaded.** Until it is present, job-side EDA
and feature engineering fall back to the `job_text` / `job_required_skills`
fields already available in the Hugging Face resume-job-fit dataset (see
below), per the project's documented fallback policy. This dataset is large —
do not load it entirely into memory; the loader in `src/data/` samples and
filters relevant records.

Download steps:
1. Download from Kaggle and extract `postings.csv` to
   `data/raw/linkedin_job_postings/postings.csv`.

## 3. Hugging Face Resume-Job Fit Dataset

Source: https://huggingface.co/datasets/batuhanmtl/job_resume_fit

Loaded directly via the `datasets` library — no manual download required:

```python
from datasets import load_dataset
dataset = load_dataset("batuhanmtl/job_resume_fit")
```

The `train` split is cached locally by Hugging Face (not committed to Git).

Verified schema (train split, 2385 rows x 10 columns):
`ID, resume_text, job_text, category, job_required_skills, resume_skill_list,
ai_matched_skills, ai_match_score, skill_string_match_score,
fuzzy_match_score`

**Important:** `ai_match_score`, `skill_string_match_score`, and
`fuzzy_match_score` are dataset-provided matching signals generated by the
dataset's own pipeline. They are **not** human recruiter decisions and must
never be described as such anywhere in this project (code, report, or app).

## Limitations of `batuhanmtl/job_resume_fit` (measured, see docs/EVALUATION.md)

- 2,385 rows but only **23 distinct job descriptions**, one per category, so job and occupation are
  confounded. Evaluation that should generalise to unseen jobs must therefore group by job
  (leave-one-job-out).
- `ai_match_score`, `skill_string_match_score` and `fuzzy_match_score` are produced by the dataset authors'
  automated pipeline. **They are not recruiter decisions.** Metrics computed against them measure agreement
  with that pipeline only.
- 2 exact-duplicate resumes (dropped) and 12 near-duplicate resume pairs (TF-IDF cosine ≥ 0.95, all within
  the same job).
- Mean score differs strongly by job (≈ 19 for Engineering vs ≈ 80 for HR).
